# Руководство: Жесткие ссылки (Hardlinks), Индексаторы и Загрузчики в Aliasarr

В этом документе подробно описана архитектура, принципы работы и пошаговая настройка **жестких ссылок (Hardlinks)**, **выборочной раздачи для приватных трекеров**, **индексаторов** и **торрент-загрузчиков** в **Aliasarr**.

---

## 1. Жесткие ссылки (Hardlinks): теория и преимущества

### Что такое Hardlink?
В операционных системах Linux, macOS и других UNIX-подобных системах файл на диске состоит из двух сущностей:
1. **Инод (Inode)** — метаданные файла и физические блоки данных на накопителе.
2. **Имя/путь к файлу (Directory Entry)** — ссылка в каталоге, указывающая на конкретный Inode.

**Жесткая ссылка (Hardlink)** — это создание дополнительного имени (пути) для того же самого Inode в файловой системе.

```
                  ┌───────────────────────────────┐
                  │   Физические данные на диске  │
                  │   (Inode #482910, размер 8 GB)│
                  └───────────────┬───────────────┘
                                  │
                 ┌────────────────┴────────────────┐
                 ▼                                 ▼
┌─────────────────────────────────┐ ┌─────────────────────────────────┐
│ /data/downloads/Show.S01E01.mkv │ │ /data/serials/Show/S01E01.mkv   │
│ (Используется торрент-клиентом) │ │ (Используется Plex / Jellyfin)  │
└─────────────────────────────────┘ └─────────────────────────────────┘
```

### Главные преимущества Hardlinks:
1. **0 байт дополнительного дискового пространства**: Файл размером 50 ГБ при создании хардлинка не дублируется. На диске расходуются те же 50 ГБ.
2. **Мгновенный импорт (0 миллисекунд)**: Создание жесткой ссылки — это атомарная операция записи указателя в файловой таблице. Даже 80-гигабайтный 4K BD-Remux связывается за доли миллисекунды без копирования блоков.
3. **Отсутствие нагрузки на дисковую подсистему**: Никаких задержек I/O, нагрузки на процессор и износа SSD/HDD.
4. **Безопасная непрерывная раздача**: Торрент-клиент продолжает сидировать исходный файл в `/data/downloads`, а медиасервер (Plex, Jellyfin, Emby) читает красиво названный файл из `/data/films` или `/data/serials`.
5. **Безопасное удаление**: Когда торрент завершает раздачу, Aliasarr удаляет файл из `/data/downloads`. При этом физические данные **НЕ удаляются** — счетчик ссылок Inode просто уменьшается с 2 до 1, и файл в медиатеке остается в 100% сохранности.

## 2. Настройка Hardlinks в интерфейсе Aliasarr

1. Откройте веб-интерфейс **Aliasarr**.
2. Перейдите в **«Настройки» (Settings)** $\to$ вкладка **«Медиатека / Папки» (Media Management)**.
3. Найдите блок **«Управление хардлинками и раздачей»**.
4. Убедитесь, что переключатель **«Использовать жесткие ссылки (Hardlinks) вместо копирования»** включен (по умолчанию включен).
5. Нажмите **«Сохранить»**.

> **Автоматический Fallback:** Если жесткую ссылку создать невозможно (например, папка загрузок и папка медиатеки находятся на разных дисках или разных пулах), Aliasarr автоматически и прозрачно переключится на безопасное копирование (`shutil.copy2`), сохранив целостность файлов.

## 3. Настройка Индексаторов (Трекеров)

Aliasarr поддерживает гибкую настройку трекеров с возможностью точечного управления сидированием для каждого источника.

### Поддерживаемые типы индексаторов:
- **Torznab** — интеграция с **Prowlarr**, **Jackett** или нативными API трекеров.
- **Nyaa.si** — прямой встроенный поиск и парсинг аниме-трекера.
- **Newznab** — поддержка Usenet-индексаторов.
- **Torrent RSS / IPTorrents / TorrentLeech** — персональные RSS-ленты раздач.

### Пошаговое добавление и настройка:
1. Перейдите в раздел **«Индексаторы» (Indexers)**.
2. Нажмите **«Добавить индексатор»** (или иконку карандаша для редактирования существующего).
3. Заполните основные параметры:
   - **Имя:** Название трекера (например, `Prowlarr - IPTorrents` или `RuTracker`).
   - **Тип:** Выберите тип индексатора (`Torznab`, `Nyaa`, `Torrent RSS` и др.).
   - **URL:** URL-адрес API трекера / агрегатора.
   - **API Key:** Ключ доступа к API (при наличии).
   - **Приоритет:** От 1 (наивысший) до 1000 (наинизший). Релизы с трекеров с более высоким приоритетом захватываются первыми.

---

### Настройка выборочной раздачи (Seeding Settings)

В форме каждого индексатора есть переключатель **«Раздавать скачанные файлы (для приватных трекеров)»**:

```
┌────────────────────────────────────────────────────────────────────────┐
│ [✔] Раздавать скачанные файлы (для приватных / рейтинговых трекеров)   │
├────────────────────────────────────────────────────────────────────────┤
│ Лимит Ratio:                 [ 1.5           ] (пусто = без ограничений)│
│ Лимит времени раздачи (часы): [ 72            ] (пусто = без ограничений)│
└────────────────────────────────────────────────────────────────────────┘
```

#### Рекомендации по настройке:
* **Публичные трекеры (RuTracker, Rutor, Nyaa, Kinozal и т.д.):**
  - Оставьте чекбокс **«Раздавать» выключенным**.
  - Файлы после скачивания будут перемещены в медиатеку, а торрент удалится из клиента, не занимая место в папке загрузок.
* **Приватные трекеры с рейтингом (IPTorrents, TorrentLeech, PTP, HDBits, Gazelle и т.д.):**
  - **Включите чекбокс «Раздавать»**.
  - **Лимит Ratio:** Укажите требуемый правилами трекера коэффициент (например, `1.0`, `1.5` или `2.0`).
  - **Лимит времени раздачи:** Укажите минимальное время сидирования в часах (например, `72` для 3 суток или `168` для недели Hit & Run правил).
  - В таблице индексаторов трекер будет помечен зеленым бейджем `Раздача 1.5x` / `Seed`.

## 4. Настройка Загрузчиков (Download Clients)

Aliasarr интегрируется с популярными торрент-клиентами через их официальные API.

### Поддерживаемые клиенты:
- **qBittorrent** (API v2)
- **Transmission** (RPC API)

### Пошаговая настройка загрузчика:
1. Перейдите в **«Настройки» (Settings)** $\to$ вкладка **«Клиенты загрузки» (Download Clients)**.
2. Нажмите **«Добавить клиента»** или выберите существующий.
3. Укажите параметры подключения:
   - **Название:** Имя клиента (например, `qBittorrent Primary`).
   - **Тип:** `qbittorrent` или `transmission`.
   - **Хост:** IP-адрес или имя контейнера (например, `192.168.1.100` или `qbittorrent` при общей Docker-сети).
   - **Порт:** Порт веб-интерфейса клиента (по умолчанию `8080` для qBittorrent, `9091` для Transmission).
   - **Логин / Пароль:** Данные авторизации в веб-интерфейсе торрент-клиента.
   - **Категория:** Категория/метка торрентов в клиенте (например, `aliasarr` или `media`).
4. Нажмите кнопку **«Проверить подключение» (Test)** для подтверждения связи.
5. Нажмите **«Сохранить»**.

---

### Как Aliasarr управляет процессом раздачи в клиенте:
1. При отправке релиза в загрузчик Aliasarr автоматически вызывает:
   - `setShareLimits` в **qBittorrent**
   - `seedRatioLimit` и `seedIdleLimit` в **Transmission**
2. Загрузчик знает персональные лимиты конкретного торрента с момента старта.
3. Фоновый модуль `DownloadsMonitor` в Aliasarr непрерывно отслеживает прогресс сидирования.
4. При достижении лимита Aliasarr автоматически удаляет завершенную раздачу из клиента и очищает временную папку `/data/downloads`.

## 5. Рекомендации по настройке Docker и ZFS / RAID

Для того чтобы жесткие ссылки работали корректно и мгновенно, все пути должны находиться **внутри одной точки монтирования (файловой системы)**.

### ❌ Неправильная конфигурация Docker (хардлинки НЕ работают):
```yaml
# При таком маппинге Docker видит /downloads и /movies как два РАЗНЫХ виртуальных диска:
services:
  aliasarr:
    volumes:
      - /mnt/storage/downloads:/downloads  # Диск 1
      - /mnt/storage/movies:/movies        # Диск 2
      - /mnt/storage/tv:/tv                # Диск 3
```
*Результат:* Файловая система вернет ошибку `EXDEV: Invalid cross-device link`, и Aliasarr будет вынужден долго копировать файл.

---

### ✔️ Правильная конфигурация Docker (Single Mount Point):
```yaml
services:
  aliasarr:
    image: ghcr.io/lqwestl/aliasarr:latest
    container_name: aliasarr
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=Europe/Moscow
    volumes:
      - ./config:/app/config
      - /data:/data                       # Единый том для всего медиа
    ports:
      - "8000:8000"
    restart: unless-stopped

  qbittorrent:
    image: lscr.io/linuxserver/qbittorrent:latest
    container_name: qbittorrent
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=Europe/Moscow
    volumes:
      - ./qbittorrent/config:/config
      - /data:/data                       # Тот же единый том
    ports:
      - "8080:8080"
      - "6881:6881"
      - "6881:6881/udp"
    restart: unless-stopped
```

### Настройка путей в Aliasarr:
- Папка загрузок: `/data/downloads`
- Корневая папка фильмов: `/data/films`
- Корневая папка сериалов: `/data/serials`
- Корневая папка аниме: `/data/anime`

### Особенности ZFS / Btrfs:
- Если `/data` — это один ZFS пул/датасет (например, RAID-Z1 из 8 дисков), создание хардлинка между `/data/downloads` и `/data/serials` занимает **0 мс** и **0 байт**.
- Если вы создаете отдельные ZFS датасеты для каждой папки (`zfs create pool/downloads`, `zfs create pool/films`), ZFS считает их отдельными файловыми системами. Для поддержки хардлинков рекомендуется хранить папки внутри единого датасета `/data`.

## 6. Жизненный цикл загрузки (Пошаговые сценарии)

```
                       ┌─────────────────────────┐
                       │   Захват релиза         │
                       │   (Grab Release)        │
                       └────────────┬────────────┘
                                    │
                                    ▼
                       ┌─────────────────────────┐
                       │ Скачивание в загрузчике │
                       │    (/data/downloads)    │
                       └────────────┬────────────┘
                                    │
                         Торрент скачан на 100%
                                    │
                     ┌──────────────┴──────────────┐
                     ▼                             ▼
         [Раздача отключена]              [Раздача включена]
         (Публичный трекер)               (Приватный трекер)
                 │                                 │
                 ▼                                 ▼
      ┌────────────────────┐            ┌────────────────────┐
      │ Перемещение файла  │            │ Создание Hardlink  │
      │   (shutil.move)    │            │     (os.link)      │
      └──────────┬─────────┘            └──────────┬─────────┘
                 │                                 │
                 ▼                                 │ 0 байт дублирования,
      ┌────────────────────┐                       │ моментальный доступ
      │ Удаление торрента  │                       ▼
      │    из клиента      │            ┌────────────────────┐
      └────────────────────┘            │ Сидирование торрента│
                                        │  в клиенте до лимита│
                                        └──────────┬─────────┘
                                                   │
                                          Лимит Ratio/Time достигнут
                                                   │
                                                   ▼
                                        ┌────────────────────┐
                                        │ Очистка торрента и │
                                        │  /data/downloads   │
                                        │(Медиатека нетронута)│
                                        └────────────────────┘
```

## 7. Диагностика и часто задаваемые вопросы (FAQ)

### Как проверить, что создался именно Hardlink, а не копия?
Подключитесь к серверу по SSH и выполните команду `ls -l` или `stat`:
```bash
ls -l "/data/downloads/Show.S01E01.mkv" "/data/serials/Show/Season 01/Show - S01E01.mkv"
```
**Признаки хардлинка:**
1. **Счетчик ссылок (вторая колонка в `ls -l`) равен `2`** (или более).
2. **Номер Inode совпадает**:
   ```bash
   stat -c "%i %n" "/data/downloads/Show.S01E01.mkv" "/data/serials/Show/Season 01/Show - S01E01.mkv"
   # Вывод:
   # 482910 /data/downloads/Show.S01E01.mkv
   # 482910 /data/serials/Show/Season 01/Show - S01E01.mkv
   ```

### Что произойдет, если я вручную удалю файл из медиатеки?
Файл в `/data/downloads` продолжит раздаваться. Удаление одного из путей лишь уменьшает счетчик ссылок. Физические данные удалятся только тогда, когда будут удалены **обе** ссылки (и из медиатеки, и из загрузок).

### Что делать при ошибке `Invalid cross-device link` в логах?
Это означает, что папка загрузок и папка медиатеки смонтированы в Docker как разные виртуальные точки монтирования либо находятся на разных физических накопителях / разных ZFS датасетах. Aliasarr в таком случае автоматически выполнит безопасное копирование. Чтобы включить настоящие хардлинки, перенастройте Docker тома на единый корень `/data:/data`.
