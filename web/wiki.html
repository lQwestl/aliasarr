1. Введение и Ключевые возможности 1. Introduction & Core Highlights

OVERVIEW

Aliasarr — это высокопроизводительный специализированный медиа-менеджер нового поколения, спроектированный для полной автоматизации поиска, скачивания, сортировки, переименования и обновления сериалов, фильмов и аниме. В отличие от стандартных решений (Sonarr, Radarr), Aliasarr с самого начала разрабатывался с глубоким пониманием специфики русскоязычных торрент-трекеров (RuTracker, Rutor, Kinozal, LostFilm, Tapochek, Nyaa и др.), нестандартных студий озвучки, паков сезонов и обновляемых раздач. Aliasarr is a specialized high-performance media automation manager designed for seamless searching, downloading, organizing, renaming, and upgrading of TV shows, movies, and anime. Built natively for both global and CIS torrent trackers, Aliasarr solves common pain points with multi-voiceover releases, season packs, and updating torrents.

Мультиязычные АлиасыMulti-language Aliases

Автоматическая агрегация русских, оригинальных, транслитерированных и ромадзи названий из TMDB, Shikimori, AniList, TVMaze и TheTVDB для 100% покрытия поисковой выдачи трекеров. Aggregates Russian, English, localized, and Romaji titles across TMDB, Shikimori, AniList, TVMaze, and TheTVDB for 100% search hit rate.

Парсер и Защита СезоновStrict Season Parser

Глубокое распознавание диапазонов серий, паков сезонов (`S01-S04`), абсолютной нумерации аниме и строгая изоляция сезонов (релиз S4 никогда не сопоставится с сезоном 1). Robust recognition of multi-episodes, season packs, anime absolute numbers, and strict season isolation (season 4 release is never remapped to season 1).

Атомарные HardlinksAtomic Hardlinks

Мгновенный импорт (0 мс) без дублирования дискового пространства (0 байт) с сохранением непрерывной раздачи для соблюдения требований приватных трекеров. Instantaneous 0ms import with 0 bytes extra storage and continuous seeding preservation for private tracker ratio compliance.

Инспекция и Защита ТоррентовTorrent Validation Guard

Анализ файлов внутри торрента в реальном времени. Автоматическая отмена и блокировка неподходящих раздач с мгновенным перезапуском поиска в фоне. Live torrent content inspection. Automatically cancels and blocklists non-matching downloads while instantly re-triggering search in background.

Custom Formats & СкорингCustom Formats Scoring

Полная поддержка Sonarr v4/v5 Custom Formats. Гибкая приоритизация релиз-групп (LostFilm, Red Head Sound, HDRezka), звуковых дорожек, HDR10+, Dolby Vision и кодеков. Full Sonarr v4/v5 Custom Formats compatibility. Flexible scoring for voiceover studios, audio codecs, HDR10+, Dolby Vision, and encoders.

Слежение за РаздачамиTracked Releases Daemon

Автоматический мониторинг «живых» обновляемых раздач (на RuTracker) и докачка новых серий по мере их выхода в рамках одного топика. Automatic tracking of live multi-episode torrent topics, auto-fetching new episodes as they are uploaded to the tracker.

Для корректной работы жестких ссылок (Hardlinks) папка загрузок торрент-клиента и папка медиатеки ОБЯЗАТЕЛЬНО должны находиться на одном физическом диске / одном ZFS датасете и монтироваться в контейнеры через единый общий корень (например, /data). 3. Архитектура системы и Сквозной пайплайн 3. Core Architecture & Subsystems Flow

ARCHITECTURE

Aliasarr построен по архитектуре асинхронного микромонолита на базе FastAPI, SQLAlchemy (SQLite/PostgreSQL) и неблокирующего планировщика задач asyncio. Ниже представлена полная схема взаимодействия всех ключевых подсистем: Aliasarr is engineered as a reactive asynchronous micro-monolith powered by FastAPI, SQLAlchemy, and an asyncio background task orchestrator. Below is the architectural blueprint of subsystem interactions:

PIPELINE Aliasarr Orchestration Flow
1 1. Metadata Providers (TMDB / Skyhook / Shikimori / AniList / TVMaze)
  • Синхронизация расписания премьер и статусов серий (Missing / Unaired)
  • Генерация мультиязычных алиасов: RU / EN / Romaji / Translit / Alternate Titles
2 2. Indexer Clients & Aggregators (Torznab / Prowlarr / Jackett / Nyaa / RSS)
  • Параллельный опрос трекеров по сгенерированным алиасам и категориям
  • Получение списков TorznabRelease (title, guid, download_url, seeders, size, pub_date)
3 3. Parser & Matcher Engine
  • Очистка мусора, извлечение сезонов, серий, паков (S01-S04), аниме номеров (01-24)
  • Строгая изоляция сезонов (S4 != S1 Guard)
  • Распознавание качества (2160p/1080p, Remux, WEB-DL), HDR/DV, аудиокодеков, студий озвучки
4 4. Decision & Ranking Engine (Custom Formats + Quality Profiles)
  • Проверка Blocklist (инфохэши, заблокированные релизы)
  • Расчет Total Score = Quality Base + Custom Formats Score + Seeders + Tracker Priority
  • Отбор абсолютного победителя (Best Release) или отказ с диагностикой причин
Захват / Grab
5 5. Download Clients (qBittorrent / Transmission)
  • Отправка торрента по download_url или .torrent файлу с категорией 'aliasarr'
  • Приоритизация файлов серий: нужным сериям Priority=1/7, лишним файлам Priority=0
Фоновый мониторинг каждые 30 сек
6 6. Downloads Monitor & Content Validator
  • Отслеживание прогресса скачивания (download_progress 0.0 .. 1.0)
  • Валидация содержимого: если раздача не содержит нужных файлов → Cancel + Blocklist + Re-search
  • Фиксация 100% готовности байт на диске
7 7. Postprocessor & Hardlink Engine
  • Атомарное создание жестких ссылок (Hardlinks) в медиатеку (0 мс, 0 байт)
  • Переименование по шаблону: {Series Title} - S{season:00}E{episode:00} {Quality Full}
  • Импорт сопутствующих файлов (.srt, .ass, .mka, .ttf, .nfo)
  • Перевод серии в статус DOWNLOADED
8 8. Tracking, Seeding & Notifications
  • Регистрация TrackedRelease (для докачки обновляемых раздач с RuTracker)
  • Контроль правил сидирования (Ratio / Time Limit) для приватных трекеров
  • Удаление исходного торрента после сидинга без удаления файла медиатеки
  • Отправка уведомлений в Telegram, Discord, Gotify, Ntfy, Webhook

5. Механизм парсинга: Алиасы, нормализация и очистка 5. Parser Deep Dive: Title Cleaning & Multi-Aliases

PARSER

Ключевая проблема международных и русскоязычных торрент-трекеров — огромное разнообразие названий одних и тех же произведений, технических тегов и мусорных меток. Движок парсинга Aliasarr реализует многоступенчатый пайплайн нормализации: Tracker titles contain arbitrary formatting, release tags, and transliterations. Aliasarr executes a multi-stage normalization pipeline:

1
Снятие технических скобок и метокStripping Technical Tags

Удаление мусорных конструкций: [H.264], (1080p), [LostFilm], {Dub}, [Files-x], сохраняя при этом информацию о качестве и студиях в структурированные атрибуты релиза.Extracts and sanitizes technical brackets while mapping tags into structured attributes.

2
Каноническая нормализация символовCanonical Character Normalization

Замена точек, подчеркиваний, дефисов и множественных пробелов на единые разделители, приведение буквы ё к е, удаление невидимых Unicode-символов и спецсимволов пунктуации.Unifies dots, underscores, dashes, strips zero-width Unicode artifacts, and normalizes Cyrillic character variants.

3
Многоуровневая генерация алиасовMulti-Level Alias Generation

Для каждого тайтла формируется взвешенный список поисковых фраз с приоритетом опроса:Generates prioritized search phrases for each show:

Пример генерации поисковых алиасов для тайтла "Неуязвимый" (2021) 
Тайтл: "Неуязвимый" (Invincible, 2021)
├── Priority 1 (Основное название):     "Неуязвимый"
├── Priority 2 (Оригинальное название): "Invincible"
├── Priority 3 (Транслитерация):        "Neuyazvimyy"
└── Priority 4 (Альтернативное TMDB):   "Invincible (2021)"

6. Сопоставление сезонов и Защита от ложного сопоставления (S4 Guard) 6. Season Matching & Strict Season Isolation

ALGORITHM

Одной из самых опасных ошибок в классических парсерах является ситуация, когда релиз с явным номером сезона (например, Сезон 4 / S4) при отсутствии 4-го сезона в базе данных ошибочно сопоставляется с 1-м сезоном. В Aliasarr внедрен алгоритм Строгой изоляции сезонов (Strict Season Guard): A classic flaw in older managers is remapping a numbered season release (e.g. Season 4 / S4) to Season 1 when Season 4 is not yet tracked in the database. Aliasarr enforces Strict Season Isolation:

Входной релиз на трекере:
"Invincible - S4 - rus WEBDL (LostFilm)"
Искомая серия в базе:
Сезон 1, Серия 1 (S01E01)
1. Извлечение сезона
label_season = 4
2. Сезон искомой серии
ep.season_number = 1
Проверка 4 != 1 → return False. Релиз строго отклоняется и никогда не скачивается для 1-го сезона!

7. Инспекция файлов внутри торрента и Авто-повтор поиска 7. Torrent File Priority & Auto-Retry Guard

MONITOR & GUARD

Aliasarr не просто доверяет названию торрента на трекере, а проводит глубокую инспекцию содержимого раздачи на всех этапах загрузки и импорта: Aliasarr performs real-time file-level inspection inside active torrents rather than relying solely on the tracker topic title:

Выборочная загрузка серийSelective Episode Priority

Если в общем паке сезонов вам нужны только серии 2-го сезона (а 1-й уже скачан), функция evaluate_torrent_file_priority автоматически выставляет файлам 1-го сезона приоритет 0 (Не скачивать), а нужным сериям — высокий приоритет. Это экономит гигабайты трафика и дискового пространства. If a multi-season pack is grabbed for Season 2 only, evaluate_torrent_file_priority assigns Priority 0 (Ignore) to Season 1 files, downloading only wanted episodes.

Защита от фейковых раздачFake / Empty Pack Defense

Если скачанный торрент оказался некорректным (файлы внутри не содержат нужных серий тайтла):
1. Раздача немедленно удаляется из загрузчика с файлами.
2. Инфохэш вносится в Черный список (Blocklist).
3. В Release Logs пишется подробное предупреждение.
4. Серии возвращаются в статус WANTED и автоматически запускается повторный автопоиск в фоне! If a torrent finishes without matching files: deleted from client, blacklisted, logged to Release Logs, reset to WANTED, and auto-retry search is triggered asynchronously.

8. Движок решений и Формула скоринга 8. Decision Engine & Release Scoring Formula

DECISION ENGINE

Когда Aliasarr опрашивает индексаторы, он получает десятки кандидатов. DecisionEngine производит математическую оценку каждого релиза по комплексной формуле: DecisionEngine computes a deterministic score for each release candidate across quality profiles, custom formats, and indexer weights:

Формула расчета финального скоринга релиза (Total Score) 
TOTAL SCORE = Quality Base Score + Custom Formats Score + Indexer Priority Bonus + Seeders Bonus

1. Quality Base Score:    Ранг разрешения и источника (Remux 2160p = 10000, 1080p WEB-DL = 7000...)
2. Custom Formats Score:  Сумма баллов совпавших правил (LostFilm = +100, Dolby Vision = +150...)
3. Indexer Priority:      Бонус приоритета трекера (Приоритет 1 = +500, Приоритет 25 = +50...)
4. Seeders Bonus:         Логарифмический бонус за количество активных сидов на трекере
Диагностика решений (Почему релиз отклонен)Decision Diagnostics (Why Release was Rejected)

В окне интерактивного ручного поиска (кнопка «Поиск релизов») колонка «Решение» наглядно объясняет вердикт движка: In the Interactive Search modal, the Decision column reports the exact verdict:

  • Заблокирован — релиз или инфохэш находится в черном списке (Blocklist).
  • Мало сидов — количество сидеров меньше значения параметра min_seeds в настройках.
  • Не входит в профиль — качество релиза не отмечено галочкой в выбранном профиле.
  • Превышен лимит размера — размер релиза выходит за рамки min_size_mb / max_size_mb.
  • Уже скачано лучшее — на диске уже имеется файл с более высоким Quality / Custom Score.

11. Жесткие ссылки (Hardlinks): Физика и Настройка 11. Hardlinks: Principles, Inodes & Storage

HARDLINKS

Жесткая ссылка (Hardlink) — это фундаментальный механизм файловых систем Linux/UNIX, позволяющий иметь несколько путей (имен файлов), указывающих на один и тот же физический блок данных (Inode) на диске: A Hardlink is an operating system mechanism allowing multiple directory entries to point to the exact same physical inode on disk:

Папка загрузок (qBittorrent)
/data/downloads/Show.S01E01.mkv

Inode #918231 (Размер 14 GB)
Используется торрент-клиентом для непрерывной раздачи (Seeding).

Медиатека (Plex / Jellyfin)
/data/media/series/Show/S01E01.mkv

Inode #918231 (Тот же Inode, 0 байт доп. места)
Красиво переименованный файл для медиасервера.

Почему Hardlinks незаменимы:Key Hardlink Advantages:
0 байт дублирования диска

Файл размером 40 ГБ не копируется. Вы экономите терабайты дискового пространства на вашем NAS / сервере.

Мгновенный импорт (0 миллисекунд)

Создание хардлинка — атомарная операция записи метаданных. Импорт 80-гигабайтного 4K Remux происходит мгновенно.

Непрерывный сидинг

Торрент-клиент продолжает сидировать исходный файл, а медиасервер читает переименованный файл в библиотеке.

Безопасное удаление

Удаление торрента удаляет только одну ссылку. Файл в медиатеке остается в 100% сохранности.

Внимание: Ошибка «Invalid cross-device link» (Errno 18)Warning: «Invalid cross-device link» Error
Хардлинки не могут работать между разными томами Docker, разными ZFS датасетами или разными дисками. Настройте единый том - /mnt/storage/data:/data для всех контейнеров. Если хардлинк невозможен, Aliasarr автоматически переключается на безопасное копирование. Hardlinks cannot span multiple Docker volume mounts or ZFS datasets. Mount a single shared root volume /data across all services. Aliasarr transparently falls back to copy mode if hardlinking fails.

12. Управление раздачей и лимитами сидирования 12. Seeding Rules & Limits Lifecycle

SEEDING

Aliasarr умеет интеллектуально управлять сидированием торрентов в зависимости от типа трекера и требований рейтинга (Hit&Run): Aliasarr provides granular seeding lifecycle management per indexer, protecting your private tracker ratio and Hit&Run requirements:

Публичные трекеры (Rutor, RuTracker и др.) Public Trackers

Чекбокс «Раздавать» выключен. Сразу после скачивания файлы связываются или перемещаются в медиатеку, а торрент удаляется из клиента для экономии места. Seeding toggle is OFF. After download finishes, files are linked/moved to the library, and the torrent task is immediately cleaned up.

Приватные трекеры (IPTorrents, Tapochek и др.) Private Trackers

Чекбокс «Раздавать» включен. Торрент удерживается в клиенте до достижения заданного Лимита Ratio или Лимита времени раздачи. Seeding toggle is ON. The torrent stays active in the client until specified Ratio Limit or Time Limit is reached.

Индикация в мониторинге «Активность» (Activity) Activity Monitor Seeding Indicators
  • Таймер с фиксированным лимитом: Отображается как 11ч 53м / 12ч с подсветкой обратного отсчета Осталось: 6м. Торрент раздается ровно до окончания лимита.
  • Бессрочная раздача (∞): Если лимит времени раздачи не задан (пусто или 0), отображается [Время раздачи] (∞) (например, 33с (∞)). Торрент остается на раздаче бессрочно до ручной остановки пользователем.
  • Коэффициент отдачи (Ratio): Отображается как Ratio: 0.06 / 1.50 (при заданном лимите) либо Ratio: 0.06.
  • Статусы клиента: seeding — активная раздача пирам; pausedup — раздача на паузе / ожидает пиров или действий в клиенте.
Автоматическое завершение и очисткаAutomatic Cleanup on Limit Completion
Когда торрент выполняет хотя бы одно из условий сидирования (достиг Ratio или отсидировал заданное количество часов), Aliasarr автоматически и безопасно удаляет раздачу из клиента и очищает временную папку загрузки. Если созданы Hardlinks, файлы в медиатеке остаются в полной сохранности. Once a seeding task satisfies its configured ratio or time requirement, Aliasarr automatically cleans up the torrent and download directory. If hardlinks were used, media files in your library remain 100% intact.

13. Спецвыпуски (Сезон 0, OVA, SP) и Ручной импорт 13. Specials, OVA & Interactive Import

SPECIALS

Спецвыпуски (Сезон 0, OVA, SP, Bonus Disc) часто имеют нестандартную нумерацию и названия на трекерах (например, «OVA 1», «LOVE Machine 2D ver», «Yoroshiku Tsucchi», «Special 3»). Чтобы исключить случайную перезапись или повреждение файлов, Aliasarr применяет надежный двухэтапный протокол: Specials (Season 0, OVA, SP) often feature non-standard naming on trackers. Aliasarr protects your library with a safe two-stage workflow:

Комбинированные релизы (Сезоны + Спешлы) Hybrid Releases (Seasons + Specials)

Основные сезоны импортируются автоматически. Спецвыпуски переводятся в режим ожидания ручного сопоставления. Папка раздачи НЕ удаляется, пока пользователь не подтвердит импорт спецвыпусков. Релизы только со спецвыпусками Specials-Only Releases

Режимы в модальном окне «Ручной импорт» Manual Import Modal Options
  • Переместить (Move): Файлы спецвыпусков перемещаются в каталог медиатеки сериала с правильными именами (S00E01, S00E02 и т.д.), а исходная папка загрузок полностью очищается после завершения импорта всех серий.
  • Скопировать / Хардлинк (Copy / Hardlink): Создает жесткие ссылки в медиатеке, сохраняя файлы в исходной папке для продолжения раздачи (Seeding) на приватном трекере.
  • Защита от дубликатов: Если несколько файлов ошибочно сопоставлены с одним и тем же спецвыпуском, интерфейс подсвечивает строки красным цветом и предупреждает о конфликте до отправки формы.

14. Служба слежения за раздачами (Tracked Releases Daemon) 14. Tracked Releases & Live Topic Monitoring

DAEMON

На русскоязычных трекерах (особенно RuTracker) релиз-группы часто выкладывают сериал в одном обновляемом топике, перезаливая .torrent файл по мере выхода новых серий (например, «серии 1-4 из 12» $ o$ «серии 1-5 из 12»). On CIS trackers (notably RuTracker), release groups update a single topic as new episodes air, updating the .torrent file from episodes 1-4 to 1-5, etc.

Демон Tracked Releases периодически опрашивает такие топики. При обнаружении обновления он автоматически докачивает только новые вышедшие серии без повторного скачивания уже имеющихся файлов. The Tracked Releases daemon periodically polls registered topic GUIDs, auto-fetching only newly added episodes without re-downloading existing media.

16. Часто задаваемые вопросы и Диагностика (FAQ) 16. Troubleshooting & FAQ

FAQ
Как проверить, что создался именно Hardlink, а не копия?How to verify Hardlink creation?

Выполните в терминале сервера команду stat -c "%i %n" <путь_в_загрузках> <путь_в_медиатеке> или ls -l. У обоих файлов будет одинаковый номер Inode, а счетчик ссылок равен 2 (или больше). Run stat -c "%i %n" <download_path> <library_path> or ls -l. Both files share the exact same Inode number with a link count of 2+.

Что произойдет, если я вручную удалю файл из медиатеки?What happens if I delete file from library?

Файл в папке загрузок продолжит спокойно раздаваться торрент-клиентом. Физические блоки данных освободятся на диске только тогда, когда будут удалены все ссылки на данный Inode. The source file in downloads continues seeding. Physical storage is freed only when all links to that Inode are unlinked.

Что делать при ошибке «Invalid cross-device link»?How to fix «Invalid cross-device link»?

Папка загрузок и папка медиатеки смонтированы в Docker как разные виртуальные устройства или лежат на разных ZFS датасетах. Настройте единую точку монтирования (например, - /data:/data) в docker-compose.yml. При возникновении этой ошибки Aliasarr автоматически переключается на безопасное копирование. Mount a single root volume (e.g. - /data:/data) across containers so both paths exist on the exact same filesystem instance.

Где посмотреть подробный ход принятия решений по автопоиску?Where to inspect auto-search logs?

Перейдите во вкладку «Release Logs» (или системные события в правом нижнем углу). Там в реальном времени протоколируются все стадии: опрос трекеров, баллы скоринга, захват, прогресс загрузки и отчет об импорте файлов. Open the Release Logs tab. Every stage (tracker queries, CF scores, grabs, download progress, and import steps) is logged in real time.
